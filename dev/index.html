ContinuousStatePopulationDynamics.jl

Continuous-state, continuous-time population dynamics in Julia.

This package owns the deterministic continuous-time generator, delay, and PSPM transport layers that were previously hosted in IntegralProjectionModels.jl. Broad stochastic continuous-time semantics are intentionally out of scope; future stochastic support should layer on top of these deterministic problem types in separate extension packages.

ContinuousStatePopulationDynamics.PSPMIPMProblem — Type
PSPMIPMProblem(structure, domain, n0, tspan;
               velocity, mortality, boundary_lower, boundary_upper,
               source, aux0, auxiliary_rhs, discretization, p, normalize)

Single-trait transport problem over a ContinuousDomain, plus optional coupled auxiliary ODE state.

Field arguments

The velocity, mortality, and source fields may be a Number (constant over the domain), an AbstractVector of per-location values, or a callable. Callables are vectorized: they are passed the entire mesh as a vector, not one location at a time. mortality and source receive the mesh midpoints (meshpoints(domain), length n); velocity receives the bin edges (bounds(domain), length n + 1), or it may return n cell values that are interpolated to faces. Supported callable signatures, tried in order, are (points, population, aux, p, t), (points, population, p, t), (points, aux, p, t), (points, p, t), (points, t, p), and (points). Because a generic closure matches the first signature it has the right arity for, write field functions against the whole-mesh-vector convention (e.g. z -> 0.2 .* z), not against a single scalar location (z -> 0.2 * z happens to work only because scalar multiplication broadcasts; z -> z^2 would not).

boundary_lower/boundary_upper are scalar fluxes (a Number or a callable returning one); they are used at an inflow edge, while outflow edges use the upwinded interior value.

Resilience operators

linearise (from ResilienceCore.jl, re-exported here) turns a problem into the operator whose metrics ResilienceCore computes: a Generator with mesh weights, the ContinuousJacobian at an equilibrium, or a PeriodicOperator over one period.

using ContinuousStatePopulationDynamics, ResilienceCore
L = linearise(prob)                  # linear (affine) problems: the operator itself
J = linearise(prob, ustar)           # any problem, at an equilibrium (needs ForwardDiff)
growth_rate(L), resilience(J), reactivity(J)
ResilienceCore.linearise — Method
linearise(prob::ContinuousIPMProblem, u = nothing; p = prob.p, t = first(prob.tspan),
          period = nothing, steps = 100, weights = ones(length(prob.u0)),
          tol = 1e-8, check = true)

The ResilienceCore operator of a continuous-time generator problem du/dt = G u + b.

Without u:

  • a generator that does not depend on the state (a matrix, or a callable (p, t) / (t, p)) and no input term gives Generator(G(p, t); weights);
  • with a constant input term b, the equilibrium u* = -G⁻¹ b (G must be stable) and the ContinuousJacobian(G, u*) of the return to it;
  • with period = T, a time-varying generator gives periodic_generator's PeriodicOperator over one period starting at t, with the generator held at the midpoints of steps equal sub-intervals. Its metrics are per sub-step period / steps (see periodic_generator). A periodic input term has no single equilibrium and is not supported.

With u, the Jacobian at the equilibrium u of to_ode_problem(prob): the route for a generator or input term that depends on the state (callables (u, p, t) or (u, t, p), which are always treated as state-dependent). u must satisfy G(u) u + b(u) ≈ 0, unless check = false, and ForwardDiff must be loaded.

Weights. The default weights are one: the demographic realisation of this problem (to_demographic_reactions) treats the state as counts per mesh bin. If your state holds densities at mesh points, pass weights = mesh_weights(prob.domain). On a uniform mesh a common weight changes no metric; it matters only on non-uniform weights.

Normalisation. With normalize = true the problem follows proportions, du/dt = G u - (1ᵀG u / 1ᵀu) u, which is not linear. Its operator is still the Generator(G): the proportions approach the stable distribution at the rate given by the gap between the real parts of the two leading eigenvalues of G, and the growth rate of G is the rate that the normalisation removes. With an input term, or a state-dependent generator, pass u.

DelayIPMProblems and demographic realisations have no single operator and throw an error.

ResilienceCore.linearise — Method
linearise(prob::PSPMIPMProblem, u = nothing; p = prob.p, t = first(prob.tspan),
          period = nothing, steps = 100, weights = mesh_weights(prob.domain),
          tol = 1e-8, check = true)

The ResilienceCore operator of a physiologically structured transport problem, discretised by its FixedMeshUpwind scheme.

Without u, the problem must be affine in its population, dn/dt = T n + b: velocity, mortality, source and boundary fluxes may depend on the trait, p and t, but not on the population, and there is no auxiliary state. The transport matrix T is assembled exactly, by applying the problem's right-hand side to the unit vectors, and checked against the right-hand side on random states; a problem that fails the check is treated as state-dependent. Then:

  • with no inflow or source (b = 0), Generator(T; weights);
  • otherwise, the equilibrium n* = -T⁻¹ b (T must be stable) and ContinuousJacobian(T, n*);
  • with period = T, the PeriodicOperator of periodic_generator over one period starting at t (only when b = 0 throughout the period), whose metrics are per sub-step period / steps.

With u = [n; aux], the Jacobian at that equilibrium of to_ode_problem(prob): the route for density dependence and for auxiliary state such as a resource. It needs ForwardDiff to be loaded.

Weights. The upwind scheme evolves densities at the mesh midpoints (the flux difference is divided by the bin width), so the default weights are mesh_weights(prob.domain), the bin width of each mesh point. A ContinuousJacobian carries no weights, so they are dropped on the affine and state-dependent routes; on a uniform mesh with no auxiliary state this changes no metric, but with auxiliary state the norm-based metrics (reactivity, amplification) treat a unit of density and a unit of each auxiliary variable alike.

Normalisation. As for ContinuousIPMProblem: without an input term the operator is that of the unnormalised problem; otherwise pass u.
